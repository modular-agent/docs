# Architecture

Modular Agent provides an asynchronous, stream-based architecture for orchestrating multiple agents. Agents communicate through message passing, and you compose them into networks with presets.

## Key Building Blocks

### ModularAgent

The central orchestrator. It manages agent lifecycles, connections, and message routing: maintaining agent instances, connection maps, and emitting/consuming `ModularAgentEvent`s. Your application (or the desktop app) talks to the system through this single entry point.

### Agent

A processing unit that receives values on **input ports**, does some work, and emits values on **output ports**. Agents run asynchronously and receive messages via channels. Examples: *Chat Completion*, *HTTP Request*, *Text Template*.

### Preset

A workflow configuration: a collection of agents and the connections between them, defined in JSON. The desktop editor edits presets visually; the runtime executes them. See [Preset Format](/concepts/preset-format).

### AgentContext

An event-scoped context that tracks data flow across agents for a single processing chain. It carries variables and frame stacks used by map/iteration operations.

### AgentValue

The union data type that flows through the system: primitives, strings, images, arrays, objects, tensors, LLM messages, and errors. See [Agent Values](/concepts/agent-values).

### AgentDefinition

Metadata and configuration specs for each agent type, generated by the `#[modular_agent]` macro. The desktop app uses definitions to render the agent catalog, ports, and config editors.

## Message Flow

```text
External Input → ModularAgent → routes via connections → Agent processes
                                                        ↓
                                          broadcasts to connected agents
                                                        ↓
                                          External outputs (ModularAgentEvent)
```

1. A value enters the network from an external input, a timer, a UI widget, or any source agent
2. `ModularAgent` routes the value along the preset's connections
3. Each receiving agent processes the value asynchronously and emits results on its output ports
4. Results propagate downstream until they reach a sink (an output agent, a side effect, or an external output)

Because the flow is **stream-based**, agents process values as they arrive. Long-running sources like screen capture, chat streams, and web sockets keep pushing values through the pipeline.

## Crate Layout

| Crate | Role |
|-------|------|
| `modular-agent-core` | Core library: orchestrator, agent trait, value types, preset loading |
| `modular-agent-macros` | The `#[modular_agent]` procedural macro (re-exported by core) |
| `modular-agent-std`, `-llm`, `-web`, ... | Agent plugin libraries |
| `modular-agent-desktop` | Visual editor app built on the core runtime |

The core library has minimal dependencies; agent implementations live in separate crates and are compiled in as plugins.
