# アーキテクチャ

Modular Agent は、複数のエージェントをオーケストレーションするための非同期・ストリームベースのアーキテクチャを提供します。エージェント同士はメッセージパッシングで通信し、プリセットによってネットワークとして組み立てます。

## 主要な構成要素

### ModularAgent

システム全体を統括するオーケストレーターです。エージェントのライフサイクル、接続、メッセージのルーティングを管理し、エージェントのインスタンスや接続マップを保持しながら `ModularAgentEvent` の送出と受信を行います。アプリケーション（あるいはデスクトップアプリ）は、この単一のエントリポイントを通してシステムとやり取りします。

### Agent

**入力ポート**で値を受け取り、処理を行い、**出力ポート**へ値を送り出す処理ユニットです。エージェントは非同期に動作し、チャネル経由でメッセージを受け取ります。たとえば *Chat Completion*、*HTTP Request*、*Text Template* などがあります。

### Preset

ワークフローの構成情報です。どのエージェントが存在し、それらがどう接続されているかを JSON で定義します。デスクトップエディタはプリセットを視覚的に編集し、ランタイムはそれを実行します。[プリセット形式](/concepts/preset-format)を参照してください。

### AgentContext

1 つの処理チェーンについて、エージェント間のデータフローを追跡するイベントスコープのコンテキストです。map や繰り返し処理で使う変数とフレームスタックを保持します。

### AgentValue

システム内を流れるデータの共用型です。プリミティブ、文字列、画像、配列、オブジェクト、テンソル、LLM メッセージ、エラーを表現します。[エージェント値](/concepts/agent-values)を参照してください。

### AgentDefinition

各エージェント型のメタデータと設定仕様で、`#[modular_agent]` マクロによって生成されます。デスクトップアプリはこの定義をもとに、エージェントカタログ、ポート、設定エディタを描画します。

## メッセージフロー

```text
External Input → ModularAgent → routes via connections → Agent processes
                                                        ↓
                                          broadcasts to connected agents
                                                        ↓
                                          External outputs (ModularAgentEvent)
```

1. 外部入力、タイマー、UI ウィジェット、あるいは任意のソースエージェントから値がネットワークに入ります
2. `ModularAgent` がプリセットの接続に沿って値をルーティングします
3. 値を受け取った各エージェントが非同期に処理し、出力ポートへ結果を送出します
4. 結果はシンク（出力エージェント、副作用、外部出力）に到達するまで下流へ伝播します

このフローは**ストリームベース**なので、エージェントは値が届いたそばから処理します。画面キャプチャ、チャットストリーム、WebSocket のような長時間動作するソースは、パイプラインへ値を送り続けます。

## クレート構成

| クレート | 役割 |
|-------|------|
| `modular-agent-core` | コアライブラリ。オーケストレーター、エージェント trait、値の型、プリセットの読み込み |
| `modular-agent-macros` | `#[modular_agent]` 手続きマクロ（core から再エクスポート） |
| `modular-agent-std`, `-llm`, `-web`, ... | エージェントプラグインライブラリ |
| `modular-agent-desktop` | コアランタイム上に構築されたビジュアルエディタアプリ |

コアライブラリの依存は最小限に抑えられており、エージェントの実装は別クレートに置かれてプラグインとして組み込まれます。
